## Adversarial Correctness — NEEDS_CHANGES → resolved

**Must-fix found:** the mandatory pre-launch deletion of the sample project — a documented,
required step before real launch (SP06 PRD §8, `sample-project.md`'s own header comment) —
broke the build two separate ways when actually carried out:

1. **The documented checklist omitted `src/pages/live/sample-project.test.tsx`.** Both PRD 06
   §8 and `sample-project.md`'s header comment listed only three items to delete
   (`sample-project.md`, `sample-project.tsx`, the `HOSTED_LIVE_PAGES` registry entry).
   Following that checklist exactly as written left a test file importing a module that no
   longer existed, which failed `npm run typecheck` — the first step of both CI workflows. Only
   `TASKS.md`'s own Task 7 precondition block had the correct four-item list.
2. **After emptying `HOSTED_LIVE_PAGES` and running the repo's own `npm run format`,** Prettier
   collapsed the now-empty object literal from `{\n}` to `{}`. `scripts/generate-sitemap.mjs`'s
   `hostedLiveSlugs()` parsed `registry.ts` with a regex that required the closing brace to sit
   on its own line (`\n};`) — a Prettier-legal but now-unmatched shape — so the regex failed to
   match and the function threw during `prebuild`, failing `npm run build` and CI before
   typecheck-adjacent gates even ran a second time.

Both are fixed, each with a real commit and a regression fixture:

## Deep Security — PASS

All 11 standard categories audited (injection, crypto, access control, hardcoded credentials,
data exposure, security misconfiguration, authentication/session failures, data integrity,
SSRF, supply chain, cross-site/prompt injection where applicable to a static site's build
tooling). No Critical or High findings. The three security defects found and fixed during SP04's
review (`vite.config.ts`'s unvalidated `liveUrl` → open-redirect-capable `firebase.json` write,
`generate-og-cards.mjs`'s path-traversal-capable `slug`-derived file write, and
`check-no-forms.sh`'s regex bypass on self-closing/multi-line JSX) were re-verified this pass —
all three fixes still hold, and no sibling instance of the same bug class was found anywhere
else in the codebase (checked: every other `fs.writeFileSync`/`fs.readFileSync` call site in
`scripts/`, every other regex-based content gate).

**Confirmed this pass:**

- No `dangerouslySetInnerHTML` anywhere in `src/` — grep confirms zero occurrences.
- Markdown content renders through `react-markdown` without `rehype-raw`, so any HTML embedded
  in a content file is escaped as literal text rather than parsed and injected — owner-authored
  content has no path to inject markup even if a `.md` file were ever compromised.
- All nine `target="_blank"` call sites across the codebase carry `rel="noreferrer"` — confirmed
  by grep, no exception.
- The consent gate (`ConsentContext`) has no bypass path — GA4's script tag and every
  `trackEvent` call site are both gated on the same resolved consent state; no code path
  fires either before the banner's decision is recorded.
- No secrets in tracked source (`grep`-checked for common credential/token shapes) or in git
  history (checked via `git log -p` across the full history for the same patterns plus known
  service-account-key JSON shapes). `.gitignore` explicitly hardens against a locally-generated
  service-account key ever being committed (SP08).
- The CI fork-PR guard is correct: both GitHub Actions workflows trigger on `pull_request`, never
  `pull_request_target` — confirmed by reading each file's `on:` block directly. This is a
  platform-level guarantee (GitHub itself withholds repo secrets from fork-PR-triggered
  `pull_request` runs), not something this repo's YAML could get wrong even if it tried; the
  `if:` guard on the deploy step is a UX nicety on top of that guarantee, not the actual
  boundary — see `08-ci-deploy-pipeline/review-2026-08-31-0930.md` for the full analysis.

**Open non-blocking notes (carried to the README's "Still requires the owner" section):**

- No CSP, `X-Content-Type-Options`, `Referrer-Policy`, or HSTS headers are configured in
  `firebase.json`. Low urgency for a static site with no user input, no auth, and no backend,
  but worth adding before or shortly after launch.
- GitHub Actions steps are pinned by floating major tag (`@v4`, `@v0`), not by commit SHA. The
  practical exposure is narrow: `actions/checkout@v4` and `actions/setup-node@v4` never see a
  secret; `FirebaseExtended/action-hosting-deploy@v0` is the only step that receives
  `secrets.FIREBASE_SERVICE_ACCOUNT_TEJITPABARI_99`, and is therefore the one worth SHA-pinning
  if this gets hardened.
- Two known `react-router` advisories exist with no fix currently available upstream (checked
  via `npm audit`); verified unreachable in this app's actual usage — the site does no dynamic
  route construction from untrusted input, no data-router loader/action pattern, and no
  server-side rendering path that the advisories' attack surface depends on.
- The three vendored Montserrat `.ttf` files (`scripts/assets/fonts/`, used only at build time by
  `satori`) still have no committed checksum, license file, or provenance record — sourced via a
  third-party mirror rather than fetched directly from Google Fonts. Low risk (build-time only,
  parsed by memory-safe Rust tooling, never served to visitors) but still open, per SP06's
  original review.
- `assertLinks` (SP02's build-time validator) doesn't scheme-validate arbitrary `href` values in
  free-text content bodies — no attack path exists today since all content is owner-authored and
  version-controlled, not user-submitted, but flagged for completeness.

## Test Coverage — GAPS → closed (branch `coverage-gaps`, merged as `98330ef`)

A dedicated coverage audit against the shipped code (not just PRD prose) found six real gaps,
none of which had ever caused a production defect but all of which left real code paths
unexercised by any test:

1. The OG-card generator's real PNG output was never actually rendered and inspected by any
   test, despite SP06's own PRD promising exactly that smoke test.
2. `parseWorkExperience` (`src/data/workExperience.ts`) had zero tests.
3. `assertImagePath`/`assertAbsoluteUrl`'s throw paths (SP02's shared validators) were never
   exercised — only their happy paths were implicitly covered via the full content corpus
   parsing successfully.
4. `parseResearch` had only a happy-path test; its malformed-fixture throw paths were untested
   (unlike `parseProjects`, which already had them).
5. `/projects` and `/research` (`ProjectsPage`/`ResearchPage`) had only a `not.toThrow()` smoke
   test — no assertion on actual rendered content, search behavior, or empty-state behavior.
6. The duplicate-slug guards in `src/data/projects.ts`/`research.ts` were untested.

All six closed on branch `coverage-gaps` (6 commits, tip `327cd44`) with real assertions, not
placeholder smoke tests:

- The OG-card test now runs the **real** `satori` → `@resvg/resvg-js` rendering pipeline (no
  mocking of the render step) and parses each generated PNG's own IHDR chunk bytes directly to
  assert the exact 1200×630 dimensions the PRD promises, rather than trusting the generator's
  return value.
- `parseWorkExperience` gained both a happy-path test and full throw-path coverage.
- `assertImagePath`/`assertAbsoluteUrl` gained explicit throw-path tests (malformed relative
  path, malformed/non-`https` absolute URL).
- `parseResearch` gained the same malformed-fixture throw-path suite `parseProjects` already had,
  ported across.
- `ProjectsPage.test.tsx`/`ResearchPage.test.tsx` are now real page-composition tests: search
  narrows results, tag filters compose with search, and the empty state renders on a
  no-match query.
- The duplicate-slug guards' tests document *why* they're structurally unreachable through two
  well-formed content files — `assertSlugMatchesFilename` forces `slug === filename`, and a flat
  content directory physically cannot hold two files with the same filename — so the test mocks
  `assertSlugMatchesFilename`'s check directly and spawns a nested `vitest` process to defeat
  Vite's `import.meta.glob` transform cache (needed because the glob result is cached per
  process, and two different fixture sets in the same process would collide). Slower than an
  in-process test, but order-independent and doesn't leak state across other test files.

**No production defect was found by any of these six new tests** — every gap was a coverage gap,
not a live bug. Merged into `website-revamp` as `98330ef` (`Merge branch 'coverage-gaps' into
website-revamp`), a clean, conflict-free merge: `coverage-gaps` was cut from `77bee53` and only
ever touched test files, while `website-revamp` had since diverged with three commits touching
non-overlapping files (the deletion of `useSectionViewTracking` and its test, and the
`generate-sitemap.mjs`/`.test.ts` Prettier-collapse fix above) — no file appears on both sides of
the diff, so `git merge --no-ff` resolved automatically with zero conflict markers.
