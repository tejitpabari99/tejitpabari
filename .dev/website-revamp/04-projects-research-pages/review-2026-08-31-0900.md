## Bug Hunter — NEEDS_CHANGES

**Must-fix:**
1. `scripts/generate-sitemap.mjs`'s `hostedLiveSlugs()` derived hosted `/live` slugs from a raw `readdirSync` scan of `src/pages/live/`, filtering `f.endsWith('.tsx') && f !== 'registry.ts'`, rather than from `HOSTED_LIVE_PAGES` in `src/pages/live/registry.ts` — the actual source of truth `routes.tsx`/`getStaticPaths` build on. Dormant at review time (no sibling `.test.tsx` files existed yet in that directory), but guaranteed to fire once SP06 Task 18 landed `src/pages/live/sample-project.test.tsx`, which also ends in `.tsx` and matches the same filter — emitting a bogus sitemap entry `/projects/sample-project.test/live`, a URL with no route, no prerendered page, and no registry entry, published straight to search engines.

**Notes (verified, no action needed):**
- The `readLiveUrls` (`vite.config.ts`) vs. `validateLiveRegistry` (`src/pages/live/registry.ts`) cross-check cannot disagree in a shipped build — the registry's eager throw fires during SSR module evaluation regardless of `closeBundle` timing.
- `useCollectionFilter`'s two-stage 200ms/600ms debounce cannot report a stale `result_count` to analytics — `results.length` is in the analytics effect's own dependency array.
- Tests that mock `@/data` correctly keep the real `sample-project` entry present, to avoid tripping the eager `validateLiveRegistry` throw.
- The earlier `og/projects/undefined.png` defect (from an prior run) is fixed at the root: `sample-project.md`'s frontmatter now starts at byte 0 of the file.

## Security — NEEDS_CHANGES
(Nothing here is externally exploitable today: static site, no backend, no auth, owner-authored content only. Still real defects in build tooling and factual site claims.)

**Must-fix:**
1. `vite.config.ts`'s `readLiveUrls` filtered only `typeof data.liveUrl === 'string'` — no scheme/host check — and `closeBundle()` wrote it verbatim into `firebase.json`'s redirect `destination`. The in-code comment claiming SP02's loader (`assertAbsoluteUrl` in `src/data/projects.ts`) validates first was proven false by reading `vite-react-ssg`'s build sequence: `closeBundle` fires during the client bundle step, while `assertAbsoluteUrl` only runs later, during SSR render. A `liveUrl` of `//evil.com/phish` (protocol-relative → open redirect off tejitpabari.com) was written to `firebase.json` before the build later aborted, leaving the corrupted file on disk.
2. `scripts/generate-og-cards.mjs`'s `readCollection()` read `slug` from frontmatter with no check against the filename, then did `path.join(ROOT, 'public/og', outDir, slug + '.png')` → `writeFileSync` — a verified arbitrary-file-write primitive. A slug of `../../../../tmp/pwned-poc` escaped `public/og/` entirely, running via the `prebuild` npm hook before any other validation.
3. `scripts/check-no-forms.sh`'s `grep -rEn '<(input|form|textarea)[ >]'` was defeated by ordinary JSX formatting — a bare `<input/>` (no space before the self-closing slash) and a Prettier-wrapped multi-line tag both slipped through unmatched. This gate backs a factual "this site has no forms" claim in the site's own `/privacy` and `/terms` copy.

**Notes (non-blocking):**
- `generate-sitemap.mjs` interpolated raw slugs into `<loc>` unescaped — no XSS/injection impact against search engines, but a correctness/robustness gap worth closing alongside Must-fix #2's sibling script.
- The three vendored Montserrat `.ttf` blobs have no committed checksum, license file, or provenance record — sourced via the third-party `gwfh.mranftl.com` (google-webfonts-helper) mirror, not fetched directly from Google. Low impact (build-time only, parsed by memory-safe Rust `satori`/`@resvg/resvg-js`, never served to visitors), but worth a provenance comment or committed `LICENSE`/checksum.
- `satori`/`@resvg/resvg-js` are lockfile-pinned with integrity hashes and only ever process owner-authored text.
- `useCollectionFilter`'s `search_query` analytics event sends the visitor's typed query to GA4 — explicitly disclosed in `/privacy` and gated behind consent.
- All `target="_blank"` links correctly carry `rel="noreferrer"`.
