## Defects found and fixed during the run

1. **`@/data` never exported the `Link` type**, so SP04 Task 7's `LinksRow.tsx` failed `npm run typecheck` (it imports `Link` from `@/data`). Fixed by `15e9b55` — `export type { Link } from './shared';` added to `src/data/index.ts`.
2. **`src/content/projects/index.ts` and `src/content/research/index.ts` were still SP02-era placeholders**, hardcoding empty `projectSlugs`/`researchSlugs` arrays. `getStaticPaths` for `/projects/:slug` and `/research/:slug` therefore always resolved to zero paths — **no project or research detail page was prerendered at all**; `dist/` had 11 pages instead of 27 (`/projects/:slug/live`, wired against the real `src/data/projects.ts` loader via `src/pages/live/registry.ts`, worked fine and masked the gap). Fixed by `0cae9d4`, rewiring both `index.ts` files to derive slugs from the real gray-matter loaders in `src/data/projects.ts` and `src/data/research.ts`. `dist/` now contains 6 top-level + 10 project + 5 research + 6 `/live` pages = 27, confirmed this run (`find dist -name index.html | wc -l` → `27`).
3. **`liveRedirectsPlugin`'s `closeBundle` hook rewrote the real, committed `firebase.json` on every `npm test` / `npx vitest run`, not just a real `vite build`.** Reproduced firsthand this run: on a clean tree, `npm test` left `firebase.json` modified (`git status --porcelain firebase.json` → ` M firebase.json`; the plugin had reformatted the JSON and injected `hosting.redirects`, sha256 changed from `e52b7ad7…` to a different hash) even though nothing in the SP04 test suite invokes a real build. Root cause: Vitest's own config loading resolves and runs `vite.config.ts`'s plugin pipeline, including `closeBundle`, even though no bundle is ever produced. Fixed by adding `apply: 'build'` to the `liveRedirectsPlugin` plugin object in `vite.config.ts` (commit `b2e81cf`), which scopes the plugin — and therefore its `closeBundle` hook — to real `vite build` runs only, leaving `vite dev` and Vitest untouched. Verified this run, real output:
   - `npm test` now leaves `firebase.json` byte-identical (`git status --porcelain firebase.json` empty; sha256 unchanged at `e52b7ad7…`) and still passes 35 files / 161 tests (162 including the new regression test below).
   - `npm run build` still regenerates `hosting.redirects` with exactly the 6 `liveUrl` projects (`clip-verse`, `creator-onboarding-tool`, `med-doc-tracker`, `crunchy-filler`, `juno`, `qgis-plugin-azure-maps-creator`) and none of the other 4 (confirmed via `node -e` parsing the built `firebase.json`).
   - `npm run build` still prerenders all 27 `index.html` files (`find dist -name index.html | wc -l` → `27`).
   - The existing `vite.config.test.ts` (SP04 Task 24) passed unmodified both before and after the fix (`git diff` on the original 6 test cases is empty) — no guard was needed there since it exercises `readLiveUrls` and the redirects transform directly, not `closeBundle`/`apply`.
   - Added one focused regression test, appended to `vite.config.test.ts` without touching its existing cases: asserts the `live-redirects` plugin object declares `apply: 'build'`. Suite is now 7/7 in that file, 162/162 overall.

## Follow-ups / new issues discovered

- `npm run build`'s `liveRedirectsPlugin` legitimately rewrites `firebase.json` in place on a local build (2-space JSON reformat plus the regenerated `hosting.redirects` array) — this is correct, expected behavior per PRD §4.6, not a defect. It does mean a local `npm run build` leaves an uncommitted working-tree diff on `firebase.json` afterward; worth a note for whoever runs a local build next, so they don't mistake it for stray changes and either discard it (fine, it regenerates deterministically) or commit it (also fine, same content either way) rather than being surprised by it.
