3. **The no-op typecheck gate.** The root `tsconfig.json` is solution-style (`"files": []` + `references`), so a plain `tsc --noEmit` checks zero files and always exits 0 — a silent no-op. Discovered during Task 26's verification. Fixed in `857e5a8`: `typecheck` is now `tsc -b --noEmit`, and `vite.config.ts` gained a `/// <reference types="vite-react-ssg" />` so `ssgOptions` typechecks. This also affected SP08's planned CI gate; SP08's `TASKS.md`/`PRD.md` were corrected in-place to specify `tsc -b --noEmit` (confirmed present in `08-ci-deploy-pipeline/TASKS.md` Task 1 and `PRD.md` §4.10 — not touched by this run). The same latent breakage exists, unfixed, in the reference app `/root/projects/juno-projects/juno-landing-page`.

4. **SP02 Task 10 — the specified `tsx` runner can never work.** TASKS.md originally specified `tsx scripts/check-launch-content.ts`. `src/data`'s loaders use `import.meta.glob`, a Vite-only build-time macro with no runtime implementation, so `tsx` throws unconditionally on import (`TypeError: (intermediate value).glob is not a function`). `vite-node` (the usual escape hatch) is not installed and is no longer a vitest 4 transitive dependency. Resolved by running the gate's logic through Vitest's own transform instead: `scripts/check-launch-content.test.ts`, invoked via `CHECK_LAUNCH=1 vitest run scripts/check-launch-content.test.ts`, with `scripts/**` excluded from default `vitest run` discovery so plain `npm test` counts stay stable. The external contract (`npm run check:launch`, exit 0 on pass / nonzero naming the offending file on failure) is unchanged — this is what SP08's CI depends on. Documented in-place in `02-content-pipeline/TASKS.md` Task 10 (not modified by this run beyond adding a status line).
